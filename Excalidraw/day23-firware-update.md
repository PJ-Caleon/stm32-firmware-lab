Why erase before write?
- It is a physical requirement with how flash memory works and a safety guard for the bootloader 

- physically, a memory is 1 and 0. When erase, the memory is all set to 1. When writing, those 1 are turned to 0. But if we write on a data that is not erased like 1100101. We cannot change those 0 to 1

- For the bootloader part, wiping the metadata first acts as a safety lock. It removes the magic number, if update fails. The MCU resets. When the bootloader starts again, it checks the metadata and sees 0xFFFFFFFF instead of the magic number and sees that the update was interrupted instead of attempting to boot to a corrupted application ^IIFhfqFw

What happens on power loss during an update?

- As explained, during an update, the metadata magic number is initially reverted to 0xFFFFFFFF. And will be computed again at the last part of the update. If power is loss, the magic number never gets computed and the bootloader wont load to application because the magic number is different ^RmKgotaI

How would you add a signature check?

- a signature check verifies the integrity of the data making sure it was not altered and is signed by a trusted source. This process involves a public key to validate the digital signature

- The project does not have one but to add one

1. Have a crypto library in the bootloader
2. key pair created. Private on PC, and Public hardcoded on MCU
3. The python update script hashes the binary and signs it using the private key
4. Data sent from python to MCU
5. MCU verifies the signature with its hardcoded public key before accepting the update ^UaF59fQJ
