GPIO Registers ^DWFHVj2R

General Purpose I/O port has four 32 bit configuration registers
- GPIOx_MODER - selecting mode
- GPIOx_OTYPER - selecting output type
- GPIOx_OSPEEDR - selecting output speed
- GPIOx_PUPDR - selecting pullup/pulldown  ^wcWj0tMg

Two 32 bit data registers
- GPIOx_IDR - input data register
- GPIOx_ODR - output data register ^rQk6S99z

A 32-bit set/reset register
- GPIOx_BSRR - bit set/ reset register  ^wwkYcCti

All GPIO have a 32 bit locking register 
- GPIOx_LCKR - locks the config ^tzLmIYOl

Two 32-bit alternate function selection registers
- GPIOx_AFRH - alternate function register high 
- GPIOx_AFRHL - alternate function register low  ^zknTXs0S

All I/O are shared in 6 ports
- GPIOA, GPIOB, GPIOC, GPIOD, GPIOE, GPIOF ^arjOeRkT

GPIO Modes Config
- 01 - makes the pin an output
- 10 - makes the pin an alternate function
- 00 - makes the pin an input 
- 11 0 makes the pin an analog ^7TCEaD60

Using the GPIO pins in RTC (Real Time Clock) supply domain
- Effect: the PC13,14,15 pins functionality is lost when the core supply domain is powered off (device enters standby mode)
- if GPIO config is not bypassed by RTC config, the pins are set in analog input  ^BEiNWaHy

Alternate Function Pins 
- they can be timer outputs
- clock signals 
- communication interfaces like SPI or USART  ^vVnr0T68

Thoughts on the building process:
1. The debounce button is created because a MCU can read a single button press as multiple press. So having a delay that pauses when a button is pressed allows the MCU to read it as one click
2. Synchronous run, I noticed even with the debounce working. When I pressed it, it wont activate automatically. The reason is timing of the blinking LED. It must run its blinking cycle before it can read from the pin again if its pressed or not. My workaround here is to reduce the blinking time of the led. And the time of blinking must be equal or smaller than the debounce delay. Which means my circuit blinks 10ms or less 
3. Another way though I did not do it and as a thought experiment, to make it run asyncronously. Meaning the mcu will continue to listen to PA0 while the circuit is also blinking. I am sure its possible but I just have not implemented it.
4. Aside from that, learning to set the port and pin is done through using the helper from the header and the pin configuration table if we want the pin to be input, output, etc ^EBXo8AbA
