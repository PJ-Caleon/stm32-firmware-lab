The CPU tells DMA to READ from I/O to MEM
or WRITE from MEM to I/O

Problem is two processor on the same bus is not possible. The CPU needs to back out for DMA to do its thing  ^RPKdTGys

To control the DMA, the CPU must tell if
- Read/Write operation
- Tell the address of the I/O
- Tell the address of the memory
- Tell the size of the block to transfer  ^5oCjoXVa

The CPU backs off until DMA is done, called CYCLE STEALING
- The DMA makes a request to use the Bus from the CPU
- The CPU acknowledges by Tri-Stating the bus by making the CPU be high impedance 'Z' become an open circuit / disconnected  ^t4rFI1OC

DMA controller for STM32
- In STM, there are 12 channels
- DMA1 has 7 channels 
- DMA2 has 5 channels 

- in the startup file, each of these channels has their own interrupt ^oeXSgxSS

Why use DMA?

- we use DMA so that I/O load is dealt directly to memory without accessing the CPU. This is to make the processor do other stuff and make the system efficient ^zZDpyiof

What race conditions exist between a DMA producer and a CPU consumer?

- The DMA and the CPU use the bus line. So what happens is the CPU backs off from the bus to allow DMA to use it ^zVGc7xmo
