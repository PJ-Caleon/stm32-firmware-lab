## Text Elements
Protocol Stack

1. Payload Generation (Host & MCU)
- a packet structure with message type, sequence number, length specifier and data payload

2. Data Integrity (CRC16-CCITT)
- checksum that validates every received byte stream before any command is executed

3. Byte stuffing (COBS)
- Consistent Overhead Byte Stuffing
- The packet delimiter byte (0x00) never appears inside the packet body
- Lets the receiver instantly re-sync if the line drops or picks up garbage bytes ^0B0Umtyh

Creating a custom binary serial communication protocol for embedded systems

1. The wire format (type, seq, len, payload, crc16)

2. COBS - sending binary over serial, there needs to be a way to mark where a packet ends. Use 0x00 as frame delimiter. COBS transforms data where if a data 0x00 is not the same as the 0x00 frame delimiter

3. Parser state machine (parser_feed)
- since the MCU receives data byte by byte by hardware. They cant wait for a whole message to arrive
- The state machine feeds on individual incoming bytes at a time
- Accumulate into a buffer, watches for 0x00 delimiter, decodes the COBS math, check CRC
- If static noise corrupts the line, it catch error and drops the garbage and resync ^2bCXdn9m

What are the ways to frame messages on a byte stream? 
- Framing a byte stream is how a receiver knows when a message starts and ends
- delimiter based with COBS
- length prefixed: start the message with the field that states its exact size ^z52GoMAq

Why include a CRC?
- to check if the message is not corrupt ^4nWcgP91

 How does a parser resynchronize after errors?
- it makes a retry by telling the pc the message sent failed and asked to resend it again
- The parser resets its state machine and discard corrupted data. Allowing it to instantly catch and lock to the next valid 0x00 frame without needing to ask the sender for re-transmission ^KrK7ylYg
