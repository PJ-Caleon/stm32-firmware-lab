Clock Configuration in STM32 ^QftDnZot

Default Speed: 8MHz ^q21eGHVN

STM32F103 has 3 diff clock sources 
- HSI Oscillator clock (High Speed Internal)
- HSE Oscillator clock (High Speed External)
- PLL clock (Phase Locked Loop), syncs its freq/phase with a reference signal ^kE0VT0zH

HSI Oscillator Clock
- Uses internal 8MHz RC oscillator 
- Can be used as sysclk or divided by 2 to be a PLL input
- Faster startup than HSE but less accurate than HSE
- Maximum sysclk is 36MHz ^lE1YSCBK

HSE Oscillator Clock
- Can be generated by ceramic oscillator or external clock
- For ceramic, the range is 4 to 16 MHz 
- HSERDY flag in Clock Control Register (RCC_CR) tells if the HSE is stable or not
- RCC_CIR is the clock interrupt register for this clock ^Qd00PiMm

PLL Clock
- Can be used to multiply the HSI or HSE output clock frequency 
- Once PLL is enabled, the parameter for clock config cannot be changed once program runs 
- RCC_CIR can be used as clock interrupt register here  ^embaREqa

Application Code ^fbrpFZdE

Set Flash Latency
- FLASH_ACR register used to enable/disable and get half-cycle access and control the flash memory access time based on CPU frequency  ^2kUxpPz1

Bits show the ratio of Sysclk period to flash access time.
Every bit increases the sysclk by 24 MHz

1. 000, (0) then sysclk is 24 MHz
2. 001, (1) then sysclk is 24 MHZ - 48 MHz
3. 010, (2) then sysclk is 48 MHz - 72 MHz ^8jFHd0Py

APB (Advance Peripheral Bus) Divisor and HSE Divisor
- Setting APB clock to be obtained after dividing HCLK by 2
- Setting the division factor of HSE to 0. The Max clock speed of APB1 is 36MHz  ^IGAVBiTG

RCC->CFGR |= RCC_CFGR_PPRE1_2;
RCC->CFGR |= RCC_CFGR_PLLXTPRE_HSE; ^SK3YWsp4

Turn on HSE
- After config division factor, switch to HSE oscillator and wait for stable state
- The HSERDY needs 6 cycles of HSE to consider HSE is off after HSEON reset
- HSEON reset turns the HSE off by clearing the HSE enable bit to 0 ^JYeX8c0Z

RCC->CR |= RCC_CR_HSEON;
while (!(RCC->CR & RCC_CR_HSERDY)); ^qOJZcysv

PLL Configuration
- The source clock is configured at PLLSRC in RRCC_CFGR. This bit needs HSE as source of PLL
- The PLL multiplication factor is modified by PLLMULL in RCCC_CFGR. Setting PLLMULL5 sets the HSE by factor of 9
- After config, setting PLLON in RCC_CR, the ready state is indicated at PLLRDY ^EQz2LY9L

RCC->CFGR |= RCC_CFGR_PLLSRC;
RCC-CFGR |= RCC_CFGR_PLLMULL9;
RCC->CR |= RCC_CR_PLLON;
while (!(RCC->CR & RCC_CR_PLLRDY)); ^tvgZrqQi

FLASH->ACR |= FLASH_ACR_LATENCY_2; // the sysclk is 48_MHz to 72 MHz ^veRGdzdi

Core clock source selection
- After PLL is ready, set main source of clk
- Modify RCC_CFGR_SWS in RCC_CFGR
- Setting RCC_CFGR_SWS_PLL enables PLL as source ^an2LFILT

RCC->CFGR |= RCC_CFGR_SW_PLL;
while (!(RCC->CFGR & RCC_CFGR_SWS_PLL)); ^6zUlXlE4

Newly generated clock
- HCLK to 72MHz: Set by flash latency 2
- Sysclk to 72MHz: Set by default * multiply Factor (8*9)
- AHBCLK to 72MHz: Same clock as HCLK
- APB1CLK to 36MHz: Set by HCLK/2
- APB2CLK to 72MHz: Was not set so default is HCLK/1 ^hjL9sKRS

Sysclk must have the highest clock rate, every other clk must be the same or lower  ^I2562OJp

Polling and Interrupts

- This is added to make the main not use so much processing power. The diagram shows the main not need to check time for time event ^dyuvkZIO

why do Wait states exist?
- Since the CPU runs faster than flash memory, we add a wait state to tell the CPU to slow down to read the flash memory. If this was not included, the CPU will not be able to read it properly  ^x4gV0EHh

What is a tick?
- It is the interval time between event A and event B
- it is based off the systick ^GvoOu54R

What is wrong with busy-wait delays?
- Any inputs that is done during a busy process wont be able to be read my the MCU
- the solution is to have millis instead of delay_ms because it is non-blocking
- Millis tells the MCU to keep runnin the loop but check if a certain ms has passed yet  ^j33WnXDc

        toggle_led();

    } ^hi1XdZzH
