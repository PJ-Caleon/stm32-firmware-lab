Event Driven Programming ^Df7MBgOv

In history, with the implementation of the mouse. Originally the PC just has to wait for inputs from the keyboard. But with the mouse. The program must wait an input from either the mouse or keyboard which the current implementation cannot do because it stalls waiting for keyboard and blocks others ^4cDdXZ3g

It brought complications, the solution was to have events/ inputs

Events drive the software ^5YWmvYfv

Event Driven Programming Skeleton Format:

1. Entry Point
2. Set attributes (OOP)
3. Set virtual function
4. Register the class 
5. Constructor of the class 
6. Event loop

    - Get message object to receive
    - wait for message to arrive in queue
    - if message not process, terminate event loop
    - else, dispatch appropriate function
    - return with status of processing  ^gZEifaPs

Properties of Event Drivent
1. The queue is asynchronous
2. Run To Completion - cannot be interrupted by other event 
3. It makes calls to application code (inversion of control) ^wAY1g8xh
