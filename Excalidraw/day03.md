Remove volatile from the register struct, compile with -O2 , and disassemble. See what the compiler removed.

If volatile is removed, the compiler will read GPIOC->IDR once and put it into register and loops forever. It did not check the hardware for the actual pin state again. The program freezes.

Adding volatile tells the compiler to not assume. The memory address can change due to external forces. The compiler must read fresh from hardware  ^KcHHr9i7

Why use BSRR instead of read-modify-write on ODR?

BSRR is a 32 bit register for STM32, it is used to set or reset a GPIO pin. 16 bit is set to high, 16 bit is set to low. We use this instead of a read-modify-write on ODR because it avoids any orphan data during the process of changing values that read-modift-write is prone too ^x3rKmsp1

Where does each of stack, heap, and .bss live?

- .bss is in RAM (Block Started by Symbol). The startup code reserves space for these in RAM and zeroes them before running main()

- Heap is in RAM. Dynamic memory allocation. Rarely used to avoid memory fragmentation

- Stack is in RAM. This is where local variables, function param, return address are stored. Lives at the top of RAM 

- The .text and .rodata is whats in ROM. .text has the compiled instructions and .rodata for the constants  ^3W73O7Kz
