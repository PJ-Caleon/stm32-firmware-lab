If the Systick ISR is deliberately slow, the while(1) that relies on the CPU having free time to run will stall. Because the CPU focuses more on the systick handler 

if the EXTI0 has lower priority than SysTick, then EXTI0_IRQHandler will be forced to wait until the systick ISR is done 

if the EXTI0 has higher priority, the systick handler will be cutoff mid-loop to focus on EXTI0 then return back to systick handler

The while(1) has the lowest priority, running in thread mode (lowest priority)

Handler Mode (interrupts/ISR): high prio
Thread Mode (While(1)): Low Prio ^8EPXXbTA

What happens on interrupt entry?
- The CPU stops its regular process to prioritize the interrupt  ^9ZBHlYXW

Why keep ISRs short?

since they are interrupts, they should be dealt with immediately or else it will affect the other program flows. Too long and lag will be noticable ^y9OWb6Oj

Why volatile on a flag shared with an ISR?

because the flag checks the button if its pressed at a state, removing the volatile will tell the compiler for flag to not always check the pin status. Volatile tells the compiler to check the variables memory instead of caching ^ByLOepKG

What is tail-chaining?

It is a technique to improve efficiency of interrupt handling by letting multiple interrupts be processed in a single execution. It is run back-to-back sequentially. Without it, the CPU pauses in between interrupts because the CPU unstacks itself which cost 12 cycles before going back to main program. Having the tail chain tells the CPU to do a series of interrupts before going back to main program ^hK8l8nzr
