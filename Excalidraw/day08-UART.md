UART
- Universal Asynchronous Receiver Transmitter
- Serial communication protocol - rules of exchanging data between two devices 
- Half duplex - one side can send at a time
- Full duplex - both can send at the same time
- Data is transmitted as frames
- The dont share a clock which allows the async
- Only through wires ^wInRGlkV

- SPI and I2C have been replacing UARTS in modern components
- Communication is done through Ethernet/USB instead of Serial ports ^KBr1gRJH

Since the clock is not shared
- both ends must have the same clock speed to transmit
- Common UART baud rates: 

4800
9600
19200
57600
115200 

- Both must use the same frame structure / parameters ^PQksTE5N

- Start/Stop bits
- data bits
- parity bits ^GvfgWrZu

Start/Stop bits
- after idle, if the data is low. Thats where the start bit occurs
- Following that low are data bits
- It is indicated at stop bit once it is high and does not go low  ^YtZ6o4t9

Data bits
- Length can be 5 - 9 bits
- Send with LEAST SIGNIGICANT BIT first

Example:
sending 7-bit ascii 'S' = 1010011
LSB order (reverse) = 1100101 

It is sent to the UART like this: ^PY5POOTU

Parity bit
- this is added for error detection which is added after the data bits and before the end bit
- They can detect ONLY a single flipped bit
- The detection depends on what type of parity.
- Even parity: all 1's from the data bits is even
- Odd parity: all 1's from the data bits is odd ^s6b0hOFX

Example:
Ascii: 1010011 - has four 1's

- if we are using even parity, the parity bit must be 0 because the current one already has four 1's
- if we are using odd parity, the data parity bit must be 1 to make the total count of 1's be odd  ^nw7StbnR

Every x of a second, the receiving device 
will check the transmit pin ^jxYcceUB

CH340G
- Tx to RX
- RX to TX
- GND to GND
- the 5v of the CH340G remains unconnected to any because the STLINK powers the board
- the 3.3V bridged to VCC is left as is to power the CH340G. It does not conflict with the power from the board ^fZaRuzHz

When configuring pins
- CRL are for pins 0-7
- CRH are for pins 8-15

- In CRH, every pin gets a 4-bit nibble (CNF+MODE) cause CRH controls pins starting from Pin 8

Bits 3:0   Pin 8   Nibble 0 (0 << 4)
Bits 7:4   Pin 9   Nibble 1  (<< 4)
Bits 11:8  Pin 10  Nibble 2  (<< 8)
....

Calculating shoft
- To find the shift in CRH, get pin number and subtract by 8 

shift = (pin number - 8) x 4

PA10:
(10-8) x 4 = 8 ^nItYoiVa
